# /acq-offer — Grand Slam Offer builder

Working on:

> $ARGUMENTS

Read `knowledge/acq/01-offers.md` first. Read the matching file in
`business-context/` if one exists.

## Process

### 1. Dream outcome
Get it in the **customer's own words**, not the operator's. Not the mechanism —
the end state. Push back if the answer describes what the business does rather
than what the customer gets.

### 2. Obstacle inventory
List every obstacle the prospect faces **before, during and after** buying.
**Target 20+.** This is the raw material for the entire offer — a short list here
produces a thin offer. Push for more before moving on.

### 3. Solutions
Map each obstacle to a solution, one-to-one. Every obstacle becomes a component.

### 4. Delivery Cube
For each component, decide:
- **Ratio:** 1-to-1 / small group / 1-to-many
- **Client effort:** high / med / low *(lower = more valuable)*
- **Medium:** in person / phone / email / text / software / physical
- **Format:** live / recorded / done-with-you / done-for-you

### 5. Consolidate
Score each component: **value to them** × **cost to you**. Keep high-value/low-cost,
cut low-value/high-cost. Present the trim explicitly — what you're removing and why.

### 6. Diagnose against the Value Equation
```
        Dream Outcome × Perceived Likelihood
VALUE = ───────────────────────────────────────
            Time Delay × Effort & Sacrifice
```
Name the **weakest term in the prospect's perception** and attack that one. Most
operators over-invest in Dream Outcome; the leverage is usually in the denominator.

### 7. Apply the five enhancers
- **Scarcity** — real caps, not fake ones
- **Urgency** — real deadlines
- **Bonuses** — each one kills a specific named objection; assign dollar values
- **Guarantee** — biggest price lever. If it's comfortable, it's too small
- **Naming** — MAGIC: Magnet, Avatar, Goal, Interval, Container

### 8. Price it
Consider: announce-increase-with-transition-date, anchor-then-discount, or
pre-payment discount. Note the effect on FECC:CAC and payback (`03-money-models.md`).

## Output

Full offer written as the customer would see it: name, promise, what's included
(with values), guarantee, price, scarcity/urgency terms. Then a short build note
covering which Value Equation term you attacked and why, and what you cut.

## Rules
- Charge for **outcomes, not access**.
- High value to them, low cost to you — every component earns its place.
- If the guarantee doesn't make the operator slightly nervous, it's too small.
- Don't accept a 5-obstacle list. The inventory is the work.
