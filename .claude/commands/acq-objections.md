# /acq-objections — objections guide

Working on:

> $ARGUMENTS

One of the artefacts ACQ AI's internal prompts are used to produce. Read
`knowledge/acq/01-offers.md` (the Value Equation drives every response) and
`knowledge/acq/05-sales.md`. Read the matching `business-context/` file if one exists.

## The principle

**Most objections are offer problems wearing a sales costume.** Before writing a
single rebuttal, check whether the objection is telling you the offer is weak. If
"it's too expensive" is the top objection, the answer is usually not a better
rebuttal — it's a bigger guarantee, a faster first win, or less required effort.

Map every objection to the Value Equation term it's really about:

```
        Dream Outcome × Perceived Likelihood
VALUE = ───────────────────────────────────────
            Time Delay × Effort & Sacrifice
```

| Objection | What it actually means | Fix at the source |
|---|---|---|
| "Too expensive" | Perceived likelihood too low for the price | Guarantee, proof, case studies |
| "I need to think about it" | No urgency, or an unspoken objection | Real deadline; ask what's unresolved |
| "I don't have time" | Effort/sacrifice too high | Do more of it for them |
| "Will this work for me?" | Perceived likelihood, specific to their case | A case study matching their situation |
| "I tried something like this" | Mechanism not differentiated | Explain why this is different, not better |
| "I need to ask my partner" | Not sold, or genuinely not the decision-maker | Establish decision process before pitching |
| "Send me some information" | Polite no | Find the real objection on the call |

## Process

### 1. Harvest the real objections
From the operator: pull the actual objections in the actual words prospects use.
Push for the top 10 minimum. Ask for call recordings or notes if they exist —
remembered objections are sanitised versions of real ones.

### 2. Classify each
Which Value Equation term? Is it a **real** objection or a **stall**? Stalls need
a different treatment: they're an unstated objection, so the response is a
question, not an argument.

### 3. Write each response
For each objection produce:
- **The response** — in the operator's voice, speakable out loud, not written prose
- **The mechanism** — why it lands
- **The proof to reach for** — the case study, number or guarantee that closes it
- **The follow-up question** — what to ask next to keep the call moving

### 4. Flag the offer fixes
Separately list objections that shouldn't be handled at all — they should be
designed out. If three of the top five map to the same Value Equation term, that
term is the actual problem and the guide is treating a symptom. Say so plainly.

### 5. Make it gradeable
Each response becomes a component on the call rubric (`/acq-sales`). If a rep
can't be scored on whether they delivered it, rewrite until they can.

## Output

A table: objection → what it really means → response → proof → follow-up
question. Then a short section headed **"Fix the offer instead"** for the ones
that shouldn't need handling.

## Rules
- Never write a rebuttal that argues someone into a bad fit — that buys refunds and churn.
- Stalls get questions, not arguments.
- If the top objection is price and the guarantee is weak, say the guarantee is the answer.
- Speakable, not readable. Read every response aloud before shipping it.
